# Secure Flow – Deployment Guide

Two repositories make up the system:

| Repository | Contents | Runs as |
|---|---|---|
| `secure-flow` (this one) | FastAPI backend, PostgreSQL schema, Stripe tools, `render.yaml` | `secure-flow-api` |
| `secure-flow-frontend` | Next.js frontend and overlay engine | `secure-flow-web` |

## 1. Configuration reference

All settings are environment variables. `.env.example` lists them with empty placeholders.
Locally, copy it to `core_backend/.env`. On Render, they are set by `render.yaml` and the dashboard.

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | yes | PostgreSQL connection string |
| `SECRET_KEY` | yes | JWT signing key, ≥ 32 random characters (generated by Render) |
| `APP_ENV` | | `development` or `production` |
| `ALLOWED_HOSTS` | | Host names the API answers to. On Render, the service's own host is added automatically |
| `CORS_ORIGIN_REGEX` | | Frontend origin(s) allowed to call the API |
| `TRUSTED_PROXY_IPS` | | Proxies whose `X-Forwarded-For` is trusted (IPs or CIDR ranges) |
| `ENABLE_MOCK_SOURCES` | | Mount the bundled mock RESO source (demo/testing) |
| `RESO_API_BASE_URL`, `RESO_API_TOKEN` | | Real RESO Web API endpoint and token (defaults to the mock) |
| `STRIPE_SECRET_KEY` | for billing | Stripe secret key (`sk_test_…` in test mode) |
| `STRIPE_WEBHOOK_SECRET` | for billing | Signing secret of the Stripe webhook endpoint (`whsec_…`) |
| `STRIPE_CATALOG_TTL_SECONDS` | | How often the tier catalog is re-synced from Stripe (default 600) |
| `CARD_FEE_PERCENT` | | Card processing fee in percent (default 5; ACH has no fee) |
| `FRONTEND_URL` | | Where Stripe Checkout and the portal return the user |
| `ENCLAVE_MAX_CONCURRENT`, `ENCLAVE_MAX_PER_USER` | | Enclave worker limits |
| `NEXT_PUBLIC_API_URL` | frontend | Public URL of the API. It is built into the frontend bundle, so redeploy after changing it |

## 2. Cloud deployment on Render

`render.yaml` is a Render Blueprint. It creates:

- `secure-flow-db`: managed PostgreSQL
- `secure-flow-api`: FastAPI backend (Python 3.11, Uvicorn)
- `secure-flow-web`: Next.js frontend (Node 20), built from the `secure-flow-frontend` repository

### Steps

1. In Render, connect the GitHub account that can access both repositories. If the frontend lives at
   a different URL, update `repo:` under `secure-flow-web` in `render.yaml`.
2. Create the Blueprint: **New → Blueprint**, pick this repository, then **Apply**. When asked,
   enter `STRIPE_SECRET_KEY` (`sk_test_…`). Leave `STRIPE_WEBHOOK_SECRET` empty for now.
3. Wait until all three resources are live. The database tables are created automatically when the
   API starts.
4. **Check the URLs.** Render normally assigns `https://secure-flow-api.onrender.com` and
   `https://secure-flow-web.onrender.com`. If a suffix was added (for example
   `secure-flow-api-ab12.onrender.com`), update these and redeploy:
   - `NEXT_PUBLIC_API_URL` on `secure-flow-web`
   - `FRONTEND_URL` on `secure-flow-api`

   `CORS_ORIGIN_REGEX` already accepts a suffixed `secure-flow-web` host.
5. **Stripe webhook.** In the Stripe Dashboard (test mode), go to **Developers → Webhooks → Add
   endpoint**:
   - URL: `https://<api host>/api/stripe/webhook`
   - Events: `checkout.session.completed`, `checkout.session.async_payment_succeeded`,
     `checkout.session.async_payment_failed`, `customer.subscription.created`,
     `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.paid`,
     `invoice.payment_failed`, `price.created`, `price.updated`, `price.deleted`,
     `product.created`, `product.updated`, `product.deleted`

   Copy the signing secret into `STRIPE_WEBHOOK_SECRET` on `secure-flow-api`. The service restarts
   on its own.
6. **Subscription tiers.** From any machine with this repository:
   ```
   pip install stripe==15.6.1
   STRIPE_SECRET_KEY=sk_test_... python tools/stripe_setup.py
   ```
   This creates the tiers defined in `tools/stripe_tiers.json`. Tiers can also be created directly
   in the Stripe Dashboard: give the product or price the metadata `tier_id`.
7. **ACH.** In Stripe settings, enable **ACH Direct Debit** (Payment methods) so bank-account
   checkout is offered.

### Verifying the deployment

| Check | Expected |
|---|---|
| `GET https://<api host>/health` | `{"status":"healthy","service":"secure-flow-api"}` |
| `https://<api host>/docs` | Swagger UI listing every endpoint |
| Open `https://<web host>`, register, sign in | Dashboard loads |
| Data flows → create a RESO flow → run it | Records are ingested from the mock RESO source |
| Sign page → draw → submit | Signature stored with UTC time and your public IP; **Verify** passes |
| Billing → pick a tier → ACH or card → Checkout | Stripe test checkout. Card `4242 4242 4242 4242`; for ACH, use Stripe's test bank account |
| Billing after payment | Subscription with tier, method, fee and total; ledger rows from webhooks |

### Notes

- Free Render services sleep after 15 minutes without traffic. The first request after that takes
  about a minute. Paid instance types stay up.
- Render's free PostgreSQL expires after 30 days. Use a paid database plan for permanent use.
- The enclave key exists only in memory and is regenerated on every restart or redeploy. Data
  encrypted to an older key must be re-submitted. This is intended.

## 3. Local and Windows 11 ARM64

Prerequisites:

- Python 3.11+ (native ARM64 build on ARM64 machines)
- Node.js 20+
- PostgreSQL 14+

`requirements.txt` pins versions that publish Windows ARM64 wheels. Where `psycopg2` has no
wheel, the pure-Python `pg8000` driver is selected automatically.

### Backend

```
python -m venv .venv
.venv\Scripts\activate
pip install -r core_backend/requirements.txt
copy .env.example core_backend\.env        # then set DATABASE_URL and SECRET_KEY
psql -U postgres -c "CREATE DATABASE secure_flow"
psql -U postgres -d secure_flow -f database-enclave/schema.sql   # optional: the API also creates tables
uvicorn core_backend.main:app --host 0.0.0.0 --port 8000 --no-proxy-headers
```

Run the tests with `pytest core_backend/tests`.

### Frontend

```
npm ci
set NEXT_PUBLIC_API_URL=http://localhost:8000
npm run build
npm start                                    # http://localhost:3000
```

`npm run validate:overlay` runs the overlay injection-proxy validation. It uses Microsoft Edge.

### Stripe locally

Use the Stripe CLI to forward webhooks:

```
stripe listen --forward-to localhost:8000/api/stripe/webhook
```

Put the printed `whsec_…` into `STRIPE_WEBHOOK_SECRET`.
